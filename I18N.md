## Introduction

Now the i18n system of day.dart contains the following keys:

- Months
- MonthsShort
- MonthsFormat (optional)
- MonthsShortFormat (optional)
- Weekdays
- WeekdaysShort
- WeekdaysMin
- AM
- PM
- RelativeTime

For example, let’s take a look at [i18n/en.dart](https://github.com/dayjs/day.dart/blob/master/lib/i18n/en.dart):

```dart
final Map<String, dynamic> Locale = {
  'Name': 'en',
  'Months': {
    1: 'January',
    2: 'February',
    3: 'March',
    4: 'April',
    5: 'May',
    6: 'June',
    7: 'July',
    8: 'August',
    9: 'September',
    10: 'October',
    11: 'November',
    12: 'December'
  },
  'Weekdays': {
    1: 'Monday',
    2: 'Tuesday',
    3: 'Wednesday',
    4: 'Thursday',
    5: 'Friday',
    6: 'Saturday',
    7: 'Sunday'
  },
  'AM': 'AM',
  'PM': 'PM',
  'RelativeTime': {
    'future': 'in %s',
    'past': '%s ago',
    's': 'a few seconds',
    'm': 'a minute',
    'mm': '%d minutes',
    'h': 'an hour',
    'hh': '%d hours',
    'd': 'a day',
    'dd': '%d days',
    'M': 'a month',
    'MM': '%d months',
    'y': 'a year',
    'yy': '%d years'
  }
};
```

You can see many of keys like `Months`, `Weekdays` ..., but where are the remained keys like `MonthsShort` mentioned above?

Because the `MonthsShort` is only a substring of the regular month string in English. So for example, the `MonthsShort` of `January` is `Jan`, take between 0 and 3.

The `WeekdaysShort` take between 0 and 3.

The `WeekdaysMin` take between 0 and 2.

But in different languages, the **Short** of months and weekdays isn't fully the same as in English.

You can view other locale files like [i18n/zh_cn.dart](https://github.com/dayjs/day.dart/blob/master/lib/i18n/zh_cn.dart) for more details.

### Month forms in dates

Locales can provide optional `MonthsFormat` and `MonthsShortFormat` maps,
indexed from 1 to 12. These forms are used for `MMMM` and `MMM` when the
month token immediately follows `D` or `DD`, separated by whitespace or
bracketed literal text. Otherwise, `Months` and `MonthsShort` are used.
Locales without these optional maps keep their existing behavior.

For example, Russian `MMMM` displays `апрель`, while `D MMMM YYYY` displays
`30 апреля 2019`. `D [day] MMMM` also uses the date form; `[D] MMMM` does not,
because the day token is escaped.

### Relative time forms

With the relative time plugin, unit entries in `RelativeTime` can be strings
or callbacks with the signature `String Function(int count, bool withoutSuffix)`.
The callback returns a template; `%d` is replaced with the absolute count.
`withoutSuffix` is true when the optional boolean argument to `from`, `to`,
`fromNow`, or `toNow` is true. The `future` and `past` entries remain strings
containing `%s`.

For example, Russian uses `минута` without a suffix, but `минуту` in
`через минуту` and `минуту назад`. German similarly uses `eine Minute` on
its own and `einer Minute` in `in einer Minute` or `vor einer Minute`.

## How To Use

For global usage:

```dart
import 'package:day/day.dart';
import 'package:day/i18n/zh_cn.dart' as zh_cn_locale;

void main() {
  Day.locale = zh_cn_locale.locale;

  final d = Day.fromString('2019-04-30T10:30:30.000Z');
}
```

For local usage:

```dart
import 'package:day/day.dart';
import 'package:day/i18n/zh_cn.dart' as zh_cn_locale;

void main() {
  final d =
      Day.fromString('2019-04-30T10:30:30.000Z').useLocale(zh_cn_locale.locale);
}
```

The local usage's priority is higher than the global usage.

## CLDR reference

The nine locales below were checked against
[Unicode CLDR JSON 48.2.2](https://github.com/unicode-org/cldr-json/tree/48.2.2/cldr-json).
The reference data comes from `cldr-dates-full/main/<locale>/ca-gregorian.json`
and `dateFields.json`, with integer plural categories checked against
`cldr-core/supplemental/plurals.json`.

| Day.dart file | CLDR locale | Language/region |
| --- | --- | --- |
| `de.dart` | `de` | German |
| `es.dart` | `es` | Spanish |
| `fr.dart` | `fr` | French |
| `ja.dart` | `ja` | Japanese |
| `ko.dart` | `ko` | Korean |
| `pt.dart` | `pt-PT` | European Portuguese |
| `pt_br.dart` | `pt` | Brazilian Portuguese |
| `ru.dart` | `ru` | Russian |
| `zh_tw.dart` | `zh-Hant` | Traditional Chinese (Taiwan) |

CLDR's likely-subtag data maps `pt` to `pt-Latn-BR` and `zh-Hant` to
`zh-Hant-TW`; these defaults explain the file-to-locale mapping above.

Month and weekday names use CLDR's `format` data (`wide`, `abbreviated`,
and `short` for `WeekdaysMin`), and AM/PM use abbreviated day periods.
Russian uses `stand-alone` month names outside dates and `format` month
names inside dates. Spanish AM/PM contain a narrow no-break space (U+202F).

The following Day.js-style choices are retained deliberately:

- German `WeekdaysMin` omits the abbreviation period (`Mo` instead of `Mo.`).
- Traditional Chinese full month names use Chinese numerals (`一月`) rather
  than CLDR's Arabic numerals (`1月`).
- Relative-time thresholds and phrases such as "a few seconds" or "a minute"
  remain humanized. CLDR's numeric patterns do not define these phrases, so
  they are not claimed to match CLDR verbatim. German and Russian inflection
  for these phrases has separate regression tests.

Numeric relative times from two minutes through years are tested against
CLDR's past/future patterns, including Russian plural boundaries. This also
standardizes Spanish and European Portuguese future phrases to `dentro de`,
Japanese spacing and `か月`, and Korean numeric months to `개월`. These are
CLDR display conventions, not a claim that all previous variants were invalid.
Traditional Chinese future times use `後` (after), not `內` (within).

`test/i18n/fixtures/cldr_48_2_2.json` contains unmodified value extracts from
that release, ordered January–December and Monday–Sunday. The fixture retains
CLDR values even for the documented display exceptions; `cldr_test.dart`
applies those exceptions explicitly. The Unicode license is included beside
the fixture. Tests require no network access.
