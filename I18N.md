## Introduction

Now the i18n system of day.dart contains the following keys:

- Months
- MonthsShort
- MonthsFormat (optional)
- MonthsShortFormat (optional)
- Weekdays
- WeekdaysShort
- WeekdaysMin
- AM
- PM
- RelativeTime

For example, let’s take a look at [i18n/en.dart](https://github.com/dayjs/day.dart/blob/master/lib/i18n/en.dart):

```dart

  'Name': 'en',
  'Months': {
    1: 'January',
    2: 'February',
    3: 'March',
    4: 'April',
    5: 'May',
    6: 'June',
    7: 'July',
    8: 'August',
    9: 'September',
    10: 'October',
    11: 'November',
    12: 'December'
  },
  'Weekdays': {
    1: 'Monday',
    2: 'Tuesday',
    3: 'Wednesday',
    4: 'Thursday',
    5: 'Friday',
    6: 'Saturday',
    7: 'Sunday'
  },
  'AM': 'AM',
  'PM': 'PM',
  'RelativeTime': {
    'future': 'in %s',
    'past': '%s ago',
    's': 'a few seconds',
    'm': 'a minute',
    'mm': '%d minutes',
    'h': 'an hour',
    'hh': '%d hours',
    'd': 'a day',
    'dd': '%d days',
    'M': 'a month',
    'MM': '%d months',
    'y': 'a year',
    'yy': '%d years'
  }

```

You can see many of keys like `Months`, `Weekdays` ..., but where are the remained keys like `MonthsShort` mentioned above?

Because the `MonthsShort` is only a substring of the regular month string in English. So for example, the `MonthsShort` of `January` is `Jan`, take between 0 and 3.

The `WeekdaysShort` take between 0 and 3.

The `WeekdaysMin` take between 0 and 2.

But in different languages, the **Short** of months and weekdays isn't fully the same as in English.

You can view other locale files like [i18n/zh_cn.dart](https://github.com/dayjs/day.dart/blob/master/lib/i18n/zh_cn.dart) for more details.

### Month forms in dates

Locales can provide optional `MonthsFormat` and `MonthsShortFormat` maps,
indexed from 1 to 12. These forms are used for `MMMM` and `MMM` when the
month token immediately follows `D` or `DD`, separated by whitespace or
bracketed literal text. Otherwise, `Months` and `MonthsShort` are used.
Locales without these optional maps keep their existing behavior.

These two optional maps are currently used only for Russian month forms.

For example, Russian `MMMM` displays `апрель`, while `D MMMM YYYY` displays
`30 апреля 2019`. `D [day] MMMM` also uses the date form; `[D] MMMM` does not,
because the day token is escaped.

### Relative time forms

With the relative time plugin, unit entries in `RelativeTime` can be strings
or callbacks with the signature `String Function(int count, bool withoutSuffix)`.
The callback returns a template; `%d` is replaced with the absolute count.
`withoutSuffix` is true when the optional boolean argument to `from`, `to`,
`fromNow`, or `toNow` is true. The `future` and `past` entries remain strings
containing `%s`.

For example, Russian uses `минута` without a suffix, but `минуту` in
`через минуту` and `минуту назад`. German similarly uses `eine Minute` on
its own and `einer Minute` in `in einer Minute` or `vor einer Minute`.

## How To Use

For global usage:

```dart
import 'package:day/day.dart';
import 'package:day/i18n/zh_cn.dart' as zh_cn_locale;

void main() {
  Day.locale = zh_cn_locale.locale;

  final d = Day.fromString('2019-04-30T10:30:30.000Z');
}
```

For local usage:

```dart
import 'package:day/day.dart';
import 'package:day/i18n/zh_cn.dart' as zh_cn_locale;

void main() {
  final d =
      Day.fromString('2019-04-30T10:30:30.000Z').useLocale(zh_cn_locale.locale);
}
```

The local usage's priority is higher than the global usage.

## Locale data conventions

Locale data follows [Unicode CLDR](https://cldr.unicode.org/translation/date-time/date-time-names)
for spelling, capitalization, punctuation, and spacing. Preserve the values
for the relevant language and region, including periods in abbreviations;
do not add or remove periods to make languages look alike. Where CLDR and
Day.js differ, CLDR's localized data is the reference. Check the source and
inheritance before adopting resolved JSON values: generic `root` fallback
patterns must not replace existing translations when localized data is missing.

All 12 bundled locales (`de`, `en`, `es`, `fr`, `ja`, `ko`, `oc`, `pt`,
`pt-br`, `ru`, `zh-cn`, and `zh-tw`) have been checked against
[CLDR JSON 48.2.2](https://github.com/unicode-org/cldr-json/tree/48.2.2/cldr-json/cldr-dates-full/main).
The CLDR locale IDs match these names except for `pt` → `pt-PT`,
`pt-br` → `pt` (Brazil), `zh-cn` → `zh` (Simplified Chinese), and
`zh-tw` → `zh-Hant` (Taiwan).

In `ca-gregorian.json`, the field mapping is:

| Day.dart field | CLDR field |
| --- | --- |
| `Months` / `MonthsShort` | `months.format.wide` / `abbreviated` |
| `Weekdays` / `WeekdaysShort` / `WeekdaysMin` | `days.format.wide` / `abbreviated` / `short` |
| `AM` / `PM` | `dayPeriods.format.abbreviated.am` / `pm` |

Russian uses `months.stand-alone` for `Months` and `MonthsShort`, and
`months.format` for `MonthsFormat` and `MonthsShortFormat`, as described above.
For example, German `WeekdaysMin` uses `Mo.`, and Traditional Chinese
`Months` uses `1月`.

Except for Occitan, numeric relative times from two minutes through years follow
the past/future patterns in `dateFields.json`, including plural forms. The plugin
retains its humanized thresholds and phrases such as "a few seconds" and "a minute";
these are not claimed to match CLDR's numeric patterns verbatim.
For Occitan (`oc`), CLDR 48.2.2's resolved relative-time data uses generic
`root` fallback patterns such as `+2 min` and `-2 min`, rather than localized
translations. The existing Occitan expressions, such as `dins 2 minutas` and
`fa 2 ans`, are therefore retained. Its abbreviated month and weekday names
are the same as the full names in CLDR.
